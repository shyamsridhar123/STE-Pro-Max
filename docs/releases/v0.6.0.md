# v0.6.0 — Automatic SkillC checks

STE-Pro Max now checks supported STE operations automatically with the original
SkillC engine. No manual staging, approval token, or product confirmation is needed.
Invalid operations still fail closed, and existing host permissions remain intact.

## What changed

- Native render/start, direct triples, gallery regeneration, narration, WAV
  synthesis, supplied helpers, and local export use the shared policy controller.
- Copilot CLI adds guarded MCP tools, scoped hooks, and a strict `ste-author`
  agent. OpenCode V2 adds guarded top-level tools and pre-execution refusal.
- Source/evidence snapshots, output hashes, metadata, actual PCM audio, workspace
  boundaries, and protected origins are checked against real files.
- Session scope follows supported native descendants and survives continuation.
  Ordinary non-STE sessions retain their normal tools and permissions.
- README, authoring guides, runtime setup, impact, credits, and validation evidence
  now describe the automatic workflow rather than the superseded manual gate.

## Compatibility and setup

This release targets automatic enforcement in **GitHub Copilot CLI 1.0.103** and
**OpenCode 2.2.6**, tested on Windows. The configured SkillC runtime is mandatory
for effectful operations. Plugin installation does not silently download Python,
SkillC, voices, encoders, or SDK dependencies.

The inspected SkillC revision is
`25cc63bf82e968da7d01e204dc6d99879b76c45b` (software version 0.3.0). See
[runtime setup and limits](../SKILLC_GATE.md#runtime-configuration) and the
[plugin guide](../PLUGINS.md).

The old `stage` and `approve` commands are removed. Export is now:

```sh
python -m ste_promax export --input-dir artifacts/report --output-dir artifacts/report-copy
```

Direct Python callers rendering raw HTML must pass `trusted_html=True` explicitly.
Successful native return types and filenames remain intact. Historical pending
manual packages are not silently migrated or authorized.

Claude Code and Codex retain the separately documented v0.5.0 skills-only route.
Their support is not evidence of equivalent mandatory host enforcement.

## Verification

The automatic implementation passed **426 tests** with no skips, Ruff, JavaScript
syntax checks, and an independent security re-review before release preparation.
Genuine authenticated Copilot runs exercised all ten STE tools, actual local
speech, exact supplied-PCM preservation, and a protected-locator refusal. A
persistently installed isolated profile also verified inherited child-tool denial
without `--plugin-dir`. OpenCode's actual client verified guarded execution,
pre-effect refusal, correct workspace binding, non-STE passthrough, and reload.

The original writing imports and historical pending package retained their hashes.
See [dated evidence and qualifications](../VALIDATION.md); test counts are not
accuracy rates or formal verification of the integration.

## Limits that remain

Copilot's outer command-hook timeouts can fail open. The dedicated strict agent
and independently guarded executors are separate controls, not an OS sandbox.
Static inspection is not browser QA. Streamed prose checks are post-generation
advisories. Hashes and admission do not prove source truth or general JavaScript
safety. Narration preparation is not an encoded movie; manual listening and word
alignment are not claimed.
