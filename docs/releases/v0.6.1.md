# v0.6.1 — STE no longer restricts other tools

**Use STE without switching off shell, file tools, Code Mode, or other integrations.**
STE now provides skills and checked native operations, not a session-wide tool policy.
Existing host permissions and other safety plugins remain unchanged.

## What changed

- OpenCode removes global tool interception, restrictive prompt/context injection,
  session tracking, inherited restrictions, automatic chat policing, and the
  obsolete `/ste-off` command. Four skills and ten native tools remain.
- Copilot removes policing hooks and the `ste-author` tool allowlist. The remaining
  hooks bind STE MCP calls to the correct workspace; they do not restrict other tools.
- Skill guidance permits normal host tools and no longer requires a new session
  or off command for unrelated work.
- Native STE tools still check their own inputs, declared evidence, output files,
  and workspace boundaries. No new approval step or bypass flag is added.

## What the checks mean

SkillC remains useful for reliable artifact production: missing evidence, stale
export inputs, and invalid outputs are errors in native STE operations. It does
not improve English or establish factual truth. Ordinary host-tool actions do
not receive native STE receipts merely because an STE skill was loaded.

The configured runtime is required for native checked operations, not ordinary
authoring. Plugin installation does not silently install runtime dependencies.
See [practical behavior and setup](../SKILLC_GATE.md) and
[validation evidence](../VALIDATION.md).

## Verification

The source passed 426 Python tests with real Copilot CLI and OpenCode client tests
enabled, 66 Node tests, JavaScript syntax checks, and the example-builder check.
Regression cases verify ordinary host tools after STE use, Copilot continuation,
exact workspace metadata, and native checks that still reject invalid inputs.
Foreign MCP calls do not enter the STE metadata watchdog or state handling.

## Upgrade

Use the [plugin update instructions](../PLUGINS.md). A marketplace pinned to
`v0.6.0` must select the new tag; updating that old pin alone retains old behavior.
The `v0.6.0` tag and release assets are not replaced.
